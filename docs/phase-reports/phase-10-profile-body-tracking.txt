SISTEM — PHASE 10 REPORT: PROFILE & BODY TRACKING
Date: 2026-10-06
Scope: docs/BUILD_PLAN.md Phase 10 (PRD §5.5): body weight log + chart, measurements over
time, progress photos (front / side / back) with side-by-side compare, Settings (units, log
out), the coach's view in the dashboard and the mobile coach mode, the ATLAS Progress
API replaced by BodyMetric, and the onboarding lb bug fix. Phase 11 was NOT started.

================================================================================
1. SUMMARY
================================================================================
- Profile has a new Body section: latest weight + change + sparkline, latest measurements,
  newest progress photos. Each card opens its own screen.
- Weight: chart with 1M / 3M / 6M / 1Y / All, tap/drag crosshair, every weigh-in listed;
  log (today or an earlier day), edit, delete in a bottom sheet.
- Measurements: pick one (chest / waist / hips / arms / thighs) for the chart; a full-screen
  form logs or edits one day; "Last: …" hints.
- Progress photos: dated front / side / back gallery; add or change one day's photos
  (camera or gallery, Daily Pump private flow, 1-hour links); Compare one pose on two days.
- Settings: weight kg | lb and measurements cm | in (body tracking only), time zone, log out.
- Coach: dashboard Body tab (two charts, full entries table, photos + compare) and the
  mobile coach Body tab (the trainee's own views, read-only). Coach values are kg / cm.
- The ATLAS Progress model / API / client code is deleted.
- Onboarding: a weight typed in lb is now stored in kg, and its 20–400 limit applies to
  that kg value (about 44.1–881.8 lb). The first completion records it as her first
  weigh-in.

================================================================================
2. DECISIONS (owner answers) AND HOW THEY WERE BUILT
================================================================================
1. Schema: User.preferences.units.length ('cm' | 'in', unset = cm). BodyMetric has a
   unique index on traineeId + date: one day per trainee. That day's weight,
   measurements and photos live in the same document. A day left with nothing in it is
   deleted.
2. kg / lb (and cm / in) apply to body tracking only. Workouts stay kg. PRD §14 backlog:
   "lb for workouts".
3. Onboarding weight:
   - Bug fix (server, onboarding.service): a weight sent with units.weight = 'lb' (or
     saved after she chose lb) is converted to kg, 2 decimals. The height field is
     labelled "(cm)" whatever she picks, so it is stored as typed. The phone shows a
     stored kg weight back in lb when she reopens the step. Also fixed: saving the
     onboarding units used to replace the whole units object. It now sets weight and
     distance one by one, so the Settings length unit survives. No onboarding wording
     changed.
   - Unit-aware limit (follow-up owner decision): the weight is converted to kg exactly as
     it is stored (2 decimals) and then checked against 20–400 kg, so lb accepts
     44.1–881.8. The unit is the one sent with the weight (same step), else the one she
     saved before (the controller reads it: onboarding.service getStoredWeightUnit). An
     error in lb reads "Weight must be a number between 44.1 and 881.8 lb." The kg
     message is unchanged. Height has no unit choice (always typed in cm), so its 50–300
     cm limit is unchanged.
   - Onboarding error text (follow-up owner decision): when saving a step, finishing, or
     editing one step from Profile fails, the screen now shows the server's own message
     (e.g. "Weight must be a number between 44.1 and 881.8 lb."). It uses the shared
     extractErrorMessage. When the server sends no message (offline, server error), it
     shows the existing generic text ("Could not save your answers. Please try again." /
     "Could not save your profile. Please try again.") instead of axios's "Request failed
     with status code 400". Only the error lines changed; no onboarding wording or flow
     changed. Loading the answers still shows its old error text (not a validation
     message).
   - First weigh-in: on the FIRST completion only, the onboarding weight (kg) is saved
     as a BodyMetric for that day in her time zone. A weight she already logged that day
     is kept. Re-completing or editing the answer later never rewrites history.
4. Settings has no notification section (comes with Phase 5b).
5. The "Change password" link is removed from Profile.
6. Compare is side by side. PRD §14 backlog: "Progress photo slider".

Things I decided inside your answers (say if you want any changed):
- API (trainee-only, requireRole('trainee')):
    GET    /api/body-metrics                      { items (newest first), measurementIds }
    PUT    /api/body-metrics/:date                { weight?, measurements? } kg / cm, null
                                                  clears → { metric | null }
    DELETE /api/body-metrics/:date                whole day, its photos too → 204
    PUT    /api/body-metrics/:date/photos/:pose   raw image (≤3 MB), replaces that pose
    DELETE /api/body-metrics/:date/photos/:pose
    PATCH  /api/users/preferences                 { units: { weight?, length? } } → { user }
  Coach: GET /api/coach/trainees/:id/body-metrics now returns the same { items,
  measurementIds } with signed photo links.
  AuthUser has `units` (defaults filled in by the server) in /auth/me and login.
- Rules: no date in the future (her time zone) or before 2000-01-01. Weight 20–400 kg,
  measurements 10–300 cm. Values kept to 2 decimals, so 140 lb shows back as 140.0 lb.
  Unknown measurement ids are rejected. The measurement list stays one server constant.
- Photos: folder sistem/progress-photos/<traineeId>, name <date>-<pose>-<random>, same
  privatePhotos service as Daily Pump (authenticated asset, only the public id stored,
  1-hour private_download_url made per request after the access check). Replace /
  remove / delete-day delete the old asset from Cloudinary.
- Editing: tap a weight row → sheet with Save / Delete (date fixed). Measurements form:
  the fields always show the chosen date's values, so picking a date that already has
  measurements edits them. Emptying a saved field clears it.
- Chart (dataviz rules): one series in --color-primary, 2px line, 4px dots with a
  background ring (only up to 40 points), hairline solid grid, clean y ticks not from 0,
  3 date labels. The crosshair snaps to the nearest date. Readout above: value, date,
  change over the range. Default range = 3M when she has older data, else All. The list
  under each chart is the table view. Arrow keys move the crosshair.
- Coach view uses the trainee's time zone for "today"; values in kg / cm.
- Dev seed: trainee 2 gets 12 weigh-ins over ~3 months and 4 measurement days (no
  photos). Added once to an existing trainee 2 if she has ≤1 body entry.
- photoCompression.ts moved from features/workouts/data to features/privatePhotos/data
  (now used by two features). PrivatePhoto got a `thumbnail` option (3:4 crop).
- Settings moved from /settings to /profile/settings so the Profile tab stays active.
- Header actions on the sub-screens use short labels ("+ Log", "+ Add"); the full text
  is their accessible name. Placeholder wording is in bodyCopy.ts and profileCopy.ts.

Old ATLAS Progress (decision: DELETE): server features/progress + /api/progress (404 now,
tested), mobile services/progress + features/progress/types. Its two readers moved to
BodyMetric:
- the Profile stats endpoint (/api/dashboard weightTrend)
- the "weigh-ins" badge in AchievementBadges, which Phase 11 reworks
