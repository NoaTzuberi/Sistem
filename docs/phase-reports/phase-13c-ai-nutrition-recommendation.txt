================================================================================
1. SUMMARY
================================================================================
- New recommendation kind `nutrition_plan` in the Phase 12 pipeline (prepare → structured JSON → validate in code → send the
  problems back, max 3 attempts → ready / failed). Runs when onboarding completes (next to the training draft, only if the
  coach has active food items) and on demand from the nutrition builder.
- Every number is computed in code by the 13a+ calculation (with the coach's goal / formula / overrides from her working
  copy, or the coach's own typed target). The model only spreads the FIXED daily portions over the meals, builds 1–3 options
  per meal from the filtered food list (aliases), and writes a summary + points to check + a coach-only "why".
- Her restrictions are enforced IN CODE before the model sees anything (the same excludedTags rules as the builder
  warnings); archived items are never sent; snack items only when the calculation gave snack portions.
- Validation: daily portions per group EXACT, every option = its meal, kosher meat + dairy, only foods that were sent,
  a re-check of the food list after the reply, plus the builder's own publish rules.
- Dashboard: an "AI nutrition draft" card in the builder (summary, "Check by hand — not checked by code" with her own
  words, points to check, Load AI draft, Generate / Regenerate) and an "AI rationale" panel for the loaded draft.
  `NutritionPlan.aiRecommendationId` links the working copy to the draft (coach-only). Nothing reaches the trainee until
  the coach publishes.

================================================================================
Owner answers (2026-10-08) — written into PRD §5.6 ("Decisions — Phase 13c"), PRD §10 and BUILD_PLAN ("Phase 13c"):

5. PRD §14 backlog: "Per-trainee food exceptions" (added as written).

What is sent (stored on the recommendation as `input`, shown to the coach under "What the AI was given"):
- Her: age in years, height / weight rounded (the calculation's values, overrides included), sex, goal ids, training
  days min–max, weight goal (target rounded to 0.5 kg + weeks left), diet type / diet styles / religious / intolerances /
  allergies as option ids, meals per day, and her own words: the details under each answer, every "other" text, foods she
  loves / dislikes — each cleaned with the Phase 12 scrubFreeText (emails / phones removed, ≤ 500 chars), labelled by where
  she wrote it. Never: name, email, any id, birth date, photos, workout / meal logs, body history.
- The calculation (final, "do not recompute"): target kcal (+ whether it is the coach's or the calculation's), BMR, TDEE,
  delta, method, weekly rate, expected weeks, unsafe pace + recommended weeks, raised to the floor, daily portions per
  group, kcal per portion.
- The meal slots (M1…) and the filtered food list: alias | group | category | name | portion | diet tags. Real ids never
  leave the server; the alias → id map stays in the database (not in the coach API).

Things I decided inside your answers (say if you want any changed):
- Meal slot names are placeholders set in code, per her meals-per-day answer: 2 Breakfast · Dinner; 3 + Lunch; 4 = the
  builder default (Breakfast · Lunch · Snack · Dinner); 5 + Afternoon snack; 6 + Evening snack. Option labels "Option A/B/C".
  The AI never writes the intro message or tips (text she sees).
- Target used: the coach's own kcal in the working copy when she typed one, else the calculation's suggestion. If neither
  exists (missing weight / height / birth date / training days, or sex other / missing without a picked formula), the
  model is not called and the coach is told what to fill in.
- "Load AI draft" replaces the meals only (asks first when the plan already exists or has options); target, intro and tips
  stay. A plan without a target takes the kcal the draft was built for (source "suggested"). Applying a template clears the
  AI link (the meals no longer come from the draft). The link is never copied into a published version.
- She skipped the nutrition step → nothing is filtered and the card says so.
- "Check by hand" always lists all of her own words (also when the model says it handled them).
- Vegetables: no vegetable items exist, so lines are protein / carb / fat (/ snack) items; the model sets vegetablesFree.
- Found and fixed a race in the Phase 12 runner while testing: if the active run finished between the duplicate-key refusal
  and the lookup, a second "Generate" answered 500. startRecommendation now tries the create once more.

Schema / contract changes:
- AiRecommendationType + 'nutrition_plan'; AiRecommendation is now a union by `type`; new AiRecommendationOf<T>,
  AiNutritionProfile / AiNutritionCalculation / AiNutritionInputSummary / AiNutritionPlanDraft (+ meal / option / line /
  free-text types); AiRecommendationLatest<R>.
- NutritionPlan.aiRecommendationId (ObjectId, default null); SaveNutritionPlanPayload.aiRecommendationId (string links,
  null clears, omitted keeps; must be a READY nutrition draft of this trainee, else 400); CoachNutritionPlan.aiRecommendationId.
- RecommendationKind: present(output, target) and presentInput(input). GET …/ai-recommendations/latest?type=nutrition_plan;
  POST …/ai-recommendations { type: 'nutrition_plan' }.
- api-client getLatestAiRecommendation / generateAiRecommendation are generic over the type (default training_plan).

The real run (Dev Trainee Two — vegetarian, kosher, lactose-free "ok in yogurt", tree nuts + "other: kiwi", no meals-per-day
answer; your dev server, recommendation 6ac790e68c036ac52fea0069):
- Ready on the first attempt, ~34 s, 5,577 input / 1,530 output / 1,956 thinking tokens. The main model (gemini-3.8-flash)
  answered 503 "high demand", so the fallback gemini-3.5-flash-lite produced it (recorded as fallbackReason).
- Calculation (code): her plan's target 1,620 kcal → 5 protein · 4½ carb · 3½ fat · 0 snack (1,605 kcal of portions).
- Foods sent: protein 10 (54 filtered out), carb 64 (1), fat 19 (13), snack 0 — ruled out: meat, poultry, fish, shellfish,
  pork, lactose, tree nuts.
- 4 meals, 2 options each, e.g. Breakfast A: eggs + tofu ½ + oats + banana ½ + tahini; Lunch A: lentils 1½ + rice 1½ + olive
  oil. Summary mentions vegetarian / kosher / tree nuts / kiwi; considerations: check lactose-free yogurt options, check the
  plant protein spread. Every check passed (exact totals, options = meals, kosher, foods allowed).
- Note: the summary quotes "1605 kcal" — a number code gave it, not one it computed.
