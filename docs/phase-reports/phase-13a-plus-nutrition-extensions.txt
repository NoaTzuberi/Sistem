1. SUMMARY
================================================================================
- Onboarding: the "Nutrition preferences" step became ONE "Nutrition & goal" screen (same step id — onboarding still has
  10 steps): accordion sections "My goal" (only for lose weight / build muscle goals, open by default), "How I eat",
  "Intolerances & allergies" (collapsed, each with a one-line summary). Chips; a details field only under a chosen item;
  "Other" needs its text. One Skip that saves nothing. Full preference list (diet styles, kosher / halal, intolerances,
  allergies incl. shellfish, loves / dislikes, meals per day) + weight goal (target + weeks or a date).
- Every option maps to diet tags (5 new tags: shellfish, pork, lactose, alcohol, high_fodmap); the builder warns on
  conflicts; keto warns on carb portions.
- Calorie calculation = the owner's method in calorieTarget.ts (pure code, never the AI): new activity table, aggressive
  fat loss −25%, a timeline method with safety caps (1%/week loss, 0.5%/week gain, 25% of TDEE, the floor), never below
  1,200, recommended portions per group. All numbers in the coach-tunable config.
- Dashboard: a "Calculation summary" card (her data, BMR, TDEE, deficit / surplus, weekly rate, expected timeline, unsafe
  pace + recommended timeline, recommended kcal + portions); the coach can override every input. A "Message to her" field.
- Trainee Nutrition tab: the coach's note (open until read, then collapsed), the day header with per-group totals (each
  opens its swap list) that is also the portion tracker (circles, ½, last 7 days, works offline), and an optional private
  photo per meal. No calorie numbers anywhere on her side.
- Coach: her week of tracking (marked / planned per group, photos) in the dashboard and read-only in coach mode.

The calculation (differences from 13a):
- Activity factors by training days: 1–2 → 1.375, 3–5 → 1.55, 6–7 → 1.725 (13a had 5 → 1.725 and 7 → 1.9; the owner's
  method has no 1.9). Sedentary 1.2 only as the coach's pick in the card.
- Goal %: fat loss −20% (top of her "moderate 15–20%"), NEW fat loss (aggressive) −25% (coach-only), recomp −10%,
  muscle gain +10%, maintenance 0 — unchanged otherwise.
- Timeline method (target + timeframe, goal fat loss / muscle gain): required kcal/day = |Δkg| × 7,700 ÷ days; capped at the
  safe limit (loss: the smallest of 1% of body weight/week, 25% of TDEE, TDEE − floor; gain: 0.5%/week). The same caps
  also apply to the goal-% method. Unsafe → "Requested pace is unsafe; recommended timeline: N weeks".
- The recommendation is RAISED to the floor (13a only flagged it); a lower target still needs the coach's confirmation.
- Dev Trainee Two in the browser (67.6 kg, 170 cm, 36, female, 2–3 days → 3 → ×1.55; target 60 kg in 8 weeks): BMR 1,398,
  TDEE 2,166, deficit −546/day, unsafe (0.95 kg/week asked, 0.49 safe — the 25% limit), recommended 1,620 kcal, 16 weeks,
  portions 5 protein · 4½ carb · 3½ fat — the numbers of the approved proposal.

Things I decided inside your answers (say if you want any changed):
- Old (13a) preference answers are rewritten to v2 once at server start (only dev data had them): kosher → religious,
  allergy notes → an "other" allergy, dislikes → foods disliked. The dev database was migrated by your running server.
- "In 12 weeks" counts from when she saved it (setAt); re-saving the same goal keeps that moment.
- Onboarding completion no longer sends the nutrition answers (the step saves them itself) — so a skipped step stays
  "not answered".
- The lactose tag is added to every dairy item ONCE per coach (a marker on her settings), so removing it from e.g.
  lactose-free milk is never undone by a re-run. Run on the dev database: 9 dairy items tagged; second run: 0.
- Coach overrides are saved with the plan (`calorieTarget.overrides`) and also sent live with the summary request, so the
  card updates while she types (an in-between value the server refuses keeps the last good numbers and shows the reason).
- "Apply" for the recommended portions was not built: the card shows them next to "Plan now"; meals stay hers to edit.
- Intro "read": stored on the server per version (User.nutritionIntroSeenVersion) — open while unseen, collapsed after,
  on every device. Changing only the intro counts as a change (a new version).
- Tracker: per group one circle per planned portion (a planned half = a small circle); marks fill from the start; ½ adds /
  takes back a half; never more than planned (server clamps). Today follows the newest version; a past day keeps the
  version it was logged with (or the one live that day). An un-marked day without photos is no document at all.
- Offline: the whole day is saved (debounced 0.8 s, last write wins), cached on the phone, retried on reconnect /
  foreground / every 15 s; a save that hangs times out after 15 s and is retried. A refused day (outside the window) is
  dropped from the queue. The last plan is cached too, so the tab opens offline.
- Meal photos: one per meal per day, only for meals in that day's plan, private (authenticated Cloudinary assets, 1-hour
  signed links, folder sistem/meal-photos/<traineeId>), replace / remove delete the old asset. Photos need a connection.
- Coach views are neutral: "2 of 4½", "Nothing marked", "Not yet", "No plan"; a thin bar in Cherry Rose on grey (no red /
  green, no %). Coach mode has a new "Tracking" tab; its Nutrition tab shows the note (collapsed) and "Daily portions".

  ketoMaxCarbPortions (+ appliedTagBackfills on the settings document).
- NutritionPlan.calorieTarget.overrides; NutritionPlan / NutritionPlanVersion.introMessage; CalorieSuggestion extended
  (method, delta, rate, timeline, timelineNote, raisedToFloor, portions; `belowFloor` removed); CoachNutritionPlan
  dayPortions / targetPortions / introMessage; NutritionPlanView intro / dayPortions; trainee response introUnseen.
- User.nutritionIntroSeenVersion.
- MealLog moved to features/mealLogs and became one document per trainee + date (planned snapshot, eaten, planId / version,
  photos [{ mealId, mealName, publicId, uploadedAt }]); the old per-meal index is dropped by syncIndexes at server start
  (the collection had no routes, so no data).
- NutritionFeatures: mealLogging removed (FEATURE_MEAL_LOGGING removed from .env.example and vitest.config).
