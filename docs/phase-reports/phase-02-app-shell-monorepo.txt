5. HOW IT WORKS (for review)
================================================================================
App state (server, apps/server/src/features/users/appState.service.ts):
  coach -> 'coach'; onboarding not complete -> 'onboarding';
  published plan -> 'home', otherwise 'waiting'.
  hasPublishedPlan() returns false until the Plan model exists (Phase 3), so every
  onboarded trainee is 'waiting' for now.
Mobile routing:
  /                        -> RootRedirect: /login, or the landing path for appState
  /onboarding              -> only in 'onboarding'
  trainee area             -> 'waiting' + 'home' (dashboard, workouts, profile,
                              /onboarding/:step edit, workout pages). Tabs stay visible
                              while waiting (decision 2); Phase 4 locks this.
  /home                    -> only in 'home' (placeholder)
  /coach/inbox|trainees|profile -> only in 'coach' (placeholders)
  Landing: onboarding -> /onboarding, waiting -> /dashboard, home -> /home,
           coach -> /coach/inbox. The Home tab points to the landing path.
Server enforcement: requireRole('coach') checks the role in the database on every call
  (not from the JWT). No coach endpoints exist yet; Phase 3 and 6 mount it.
promote:coach: refuses NODE_ENV=production. For a non-local database (any
  mongodb+srv URL or non-localhost host) it refuses unless --allow-remote is given,
  and it always prints the host/db (never credentials) before writing.
