5. API
================================================================================
All need a session (401 without). Every call only touches the caller's notifications.
  GET   /api/notifications?limit=1..50 (default 20)&before=<id>&unread=true|false
        -> { items, unreadCount, nextCursor }      newest first
  GET   /api/notifications/unread-count  -> { unreadCount }
  PATCH /api/notifications/:id/read      -> { notification }   404 if not hers / missing
  POST  /api/notifications/read-all      -> { unreadCount: 0 }
Notifications are never created or deleted through the API.

       curl -s -X POST localhost:5002/api/auth/login -H 'Content-Type: application/json' \
         -d '{"email":"coach@sistem.dev","password":"sistem-dev-1234"}'
       curl -s localhost:5002/api/notifications -H "Authorization: Bearer <token>"
     -> one 'trainee_onboarded' item with the trainee's id and name, readAt null,
        unreadCount 1.
  3. PATCH /api/notifications/<id>/read -> readAt is set; unread-count returns 0.
  4. The same list with the trainee's token -> empty (she never sees the coach's).
  There is no screen for this yet (coach Inbox = Phase 6b).
