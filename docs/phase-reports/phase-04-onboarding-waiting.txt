================================================================================
1. SUMMARY
================================================================================
- Onboarding resumes: every step is saved to the server before moving on (Continue and
  Skip), and a fresh mount (reload, another device) restores the answers and opens the step
  after the last saved one. Finishing lands wherever the server says (the waiting screen).
- New waiting screen (/waiting): full screen, no tab bar, logo, 4 icon slots, title,
  48h countdown, message, Log Out. While waiting it is the ONLY trainee screen; Profile /
  Workouts now need a published plan.
- Countdown uses server time only: GET /api/onboarding/waiting returns serverTime +
  planDueAt (onboardingCompletedAt + 48h, the 48h lives on the server). The app adds elapsed
  time from the device's monotonic clock, so changing the phone's clock does not move it.
- The same call is polled every 30s and when the app returns to the foreground; when a plan
  is published the trainee is moved to Home automatically.
- After 48h with no plan: the countdown is hidden and the temporary overdue message is shown.
- Server fires the internal 'trainee.onboarded' event once, on the first completion only
  (apps/server/src/events/appEvents.ts). Nothing listens yet — Phase 5 hooks push into it.
- /dashboard route removed; DashboardPage and its widgets are untouched in the repo.

2. DECISIONS (owner answers)

   import it in features/waiting/data/waitingIcons.ts and set it as the slot's `src`.
   Empty slots show a dashed, numbered box.
