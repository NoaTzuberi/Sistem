Contrast audit — white text disappearing (dashboard + trainee app)
==================================================================
Date: 2026-10-15. Not a numbered phase: a global fix done before further design work.

Summary
-------
- Root cause of most "white text on light cards": `--color-on-hero-muted` was defined TWICE in tokens.css. The second
  copy (white 80 %, meant for the achievements hero) overrode the first (charcoal 70 %), so every caption on the light
  hero cards (overview hero stats, goal card, key numbers, AI plan card, week ticks, waiting list, retention, start
  cards, workout hero, issue panel, notifications) rendered near-white. The hero now uses its own `--color-on-ach-hero-muted`.
- Every rule that puts white text / icons on a fill was checked against WCAG AA (4.5:1; 3:1 for 18px+ or bold 14px+ and
  for icons). Failing fills moved to new contrast-safe tokens; light tags use colored ink on a tint; gradients under
  white text were darkened or switched to dark text; disabled pink buttons are soft pink + Cherry text, no opacity.
- New dev check `scripts/contrast-audit.mjs` (`npm run lint:contrast`, part of `npm run lint`). It found 27 problems
  before the fixes (incl. colored text that was too light, not only white) and finds 0 now.

amber #D9952B 2.53 · --solid-amber #946200 5.24 · faded pink #FFB3D1 ≈ 1.9.
Inks on tints: #A50047/#FFE3EE 6.49 · #8A4A00/#FFF4E5 6.31 · #5B2FD6/#EFE7FF 6.22 · #0066B8/#E1F1FF 5.07 · #7A5600/#FFF4D6 6.07.

Deviations from the brief (numbers above)
- Orange solid: the brief's #C75A00 is 4.29:1 with white, under 4.5 for small text → --solid-orange #B85300.
- Blue ink: the brief's #0070C9 on #E1F1FF is 4.38:1 → --ink-blue #0066B8 (#0070C9 stays the solid blue under white).
- Small white text on Neon Pink (badges, tags, step / check marks, 12px buttons) → --solid-pink #D4005C (the existing
  "ring-mid" pink). Pink buttons with bold 14px+ labels keep Neon Pink (3.83 passes 3:1).
- Token names follow the brief (--on-pink, --tint-*, --ink-*), plus --solid-* (white-text fills) and --disabled-bg / -ink.

How to test
-----------
1. npm run lint            → oxlint + i18n audit + "Contrast audit: … no findings."
2. npm run lint:contrast   → the check alone. To see it fail: set `.tag-solid { background-color: var(--color-workout-3) }`
                             and run it again (then undo).
3. npm run build -w @sistem/dashboard && npm run build -w @sistem/mobile   (both built here)
4. Manual (npm run dev:all, seed:dev):
   - Overview: hero stat captions, "waiting" list, week ticks are dark, not white.
   - Trainee profile: Goal card captions and Key numbers labels dark; Achievements hero readable on the right (Hebrew).
   - Nutrition builder: "פרסום" while blocked = soft pink + Cherry text; recommended kcal card; goal "gain"; budget pills.
   - Plan builder: the orange (3rd) and blue (4th) workouts — selected tab, "required" badge, "+ add" hover, thumbs.
   - Exercise library: pressed pattern chips (tint + ring), family tiles (dark letters).
   - Mobile: onboarding "Next" disabled = soft pink + Cherry; while saving it stays pink with the white spinner;
     selected chips; interval timer work screen; login button disabled vs busy.
   I did not open the apps in a browser for this change — please look at the screens above.

Known issues / TODOs
--------------------
- Visible design changes the owner should approve: the achievements hero is now Cherry → #D4005C with faint glows
  (the bright pink / peach end is gone); the quick-view avatar gradients are deeper; the selected onboarding chips, interval
  work screen and small pink badges use #D4005C; pressed pattern chips use tint + ring instead of a solid fill; family tiles
  and exercise thumbs use dark / colored ink on light tints.
- The check reads one rule at a time. It skips gradients, photos, SVG / canvas colors, and text whose background comes
  from an ancestor; those were reviewed by hand in this pass. New gradients under white text need the same eye.
- The brief says "keep aria-disabled": the onboarding "Next" and the auth submit use the native `disabled` attribute
  (unchanged); the dashboard Button / PillButton styles now cover both `:disabled` and `[aria-disabled='true']`.
- WCAG exempts disabled controls; the disabled styles were changed because the brief asked for it.
- `--color-text-muted` and `--color-error` are still TEMPORARY owner values; the check will catch a new value that fails.
