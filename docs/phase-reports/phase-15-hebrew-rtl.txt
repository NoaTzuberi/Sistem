SISTEM — PHASE 15 REPORT: HEBREW (DEFAULT) & RIGHT-TO-LEFT, ENGLISH AS AN OPTION
Date: 2026-10-08
Scope: docs/BUILD_PLAN.md "Phase 15" (PRD §11 "Language", §12) with the owner's answers of 2026-10-08. No other phase was started.

================================================================================
1. SUMMARY
================================================================================
- Hebrew is the default language of the mobile app and the dashboard, right-to-left everywhere; English is per user
  (User.preferences.language, AuthUser.language, PATCH /api/users/preferences { language }), switched in Settings (mobile),
  coach Profile (mobile), the dashboard top bar and the login screens — at once, without a reload, saved on the server.
- Every UI text moved into copy files (1,673 entries incl. server messages), typed so Hebrew and English can't drift; plurals via
  Intl.PluralRules; dates, weekdays and numbers via Intl in the language on screen. Own small helper — no new dependency.
- The server answers every error as { code, message } in the request's language (the clients send Accept-Language); email and
  (later) push are built in the user's saved language; AI drafts write their coach texts in the coach's language.
- RTL: all CSS is logical (no left / right left), left/right chevrons mirror, charts keep time left → right, numbers and
  arithmetic stay readable inside Hebrew text, the corner cuts mirror.
- packages/tokens/tokens.css is now THE single file for every design value of both apps (per-language font tokens with a Hebrew
  system-font placeholder, type scale, colors, spacing, cuts, borders, shadows, motion, opacity, layers, breakpoints, touch).
- Two checks: `npm run lint` runs an audit for hard-coded text / fixed locales / physical CSS; `npm test` runs a parity test
  (same keys, same {placeholders}, the plural forms each language needs — also the server catalogs).

================================================================================
2. DECISIONS AND HOW THEY WERE BUILT
================================================================================
Owner answers (2026-10-08) — written into PRD §11 ("Decisions — Phase 15") and BUILD_PLAN "Phase 15":
1. Own small i18n helper, no new dependency.
2. Charts keep the time axis left → right in both languages.
3. No font decision now: per-language font tokens; current Latin fonts for English; a Hebrew system-font placeholder; no new
   font files. packages/tokens = the single file for every design variable. Font suggestions below (section 7), not applied.
4. Neutral forms for buttons and labels; feminine forms for sentences addressing the user.
5. AI summaries and rationales in the coach's language.
6. The logo stays in English exactly as it is — never translated or mirrored.

The i18n helper (packages/shared/src/i18n — about 2 kB):
- `defineCopy(he, en)` per feature: `features/<f>/copy/he.ts` (primary, `as const`) + `en.ts` typed `CopyShape<typeof he>` (a
  missing / extra key fails the build) + `index.ts`. App-level texts in `apps/*/src/copy`. Texts both apps show, every
  option / status / unit / achievement label and the display helpers' wording in `packages/shared/src/copy`.
- `useCopy(copy)`, `useI18n()` → { language, direction, setLanguage, plural }, `fill('{name}', vars)`,
  `plural({ one, two, other })` (Hebrew needs one / two / other), Intl helpers `dateFormat`, `formatNumber`, `formatRelative`,
  `weekdayName` / `dayName` (replaces DAY_NAMES; Sunday first), bidi helpers `isolateLtr` / `isolateAuto`.
- Every display helper of @sistem/shared takes `language` as its last argument (describeTargets, formatWeight, describeAchievement,
  buildOnboardingSections, describeCoachNotification, …). Removed constant label maps (TRAINEE_STATUS_LABELS, FOOD_GROUP_LABELS,
  DIET_*_LABELS, STATUS_FILTERS, WEEK_RELATION_LABELS, DAY_NAMES, …) — replaced by the copy / functions.
- `I18nProvider` (outermost in both apps) keeps <html lang dir> in step; index.html defaults to he/rtl and an inline script applies
  the device's last language before the first paint. `useUserLanguage(user.language)` — her saved language wins after login.
  Sign-up sends the language on screen, so a new account keeps it.
- Code that runs later (effects, async callbacks) reads `copy[getActiveLanguage()]`, so a load never depends on the language.
- Bundle impact: the helper is ~2 kB; both locales are bundled (instant switch, offline). Mobile 592 kB → 651 kB (201 kB gzip),
  dashboard 526 kB (162 kB gzip). Lazy-loading the inactive locale can join the "split the bundle" backlog item.

Onboarding (protected): only text changed. options.ts / activities.ts keep their ids, order and emoji; labels come from the shared
copy by id (onboardingOptions.*), so the coach now reads the same option labels (in her language) instead of humanized ids. Steps,
logic, saving, validation and videos are untouched.

Server (apps/server/src/i18n):
- `msg(code, params)`, `LocalizedError`, `sendError(res, status, msg)` → { code, message } worded per request (Accept-Language;
  Hebrew when absent). Params may be nested messages or lists (field labels, food groups, diet tags).
- Validators return codes; plan / nutrition issues keep their indexes and get `message` per request (`localizeIssues`,
  `localizeNutritionIssues`; nutrition issues keep their own stable `code`). The model still gets the issues in English.
- `users/userLanguage.ts getUserLanguage()` for texts outside a request: the password-reset email is now in her language (RTL for
  Hebrew); Phase 5b push will use the same path (notifications still store type + data only).
- AI drafts: training-plan-v2 / nutrition-plan-v2 prompts ask for the coach's language (also the workout titles); meal slot names and
  "Option A/B/C" (א/ב/ג) are written in the coach's language; failures are stored as code + params and worded when read.
- Default meal names of a new nutrition plan (dashboard) are written in the coach's language; once saved they are her content.

RTL:
- CSS: 101 physical declarations → logical (margin/padding/border-inline-start|end, inset-inline-start|end, text-align start|end,
  float inline-start). Kept physical with a `physical:` comment: a centered dot (left:50% + translate) and the countdown bar's
  transform-origin (mirrored by an RTL rule).
- Mirrored: every left/right chevron (`className="flip-rtl"`, CSS `scale: -1 1`), text arrows in back links / "next" hints (in the
  copy: ← / →). Not mirrored: play / pause / skip, check, clock, sound, camera, +/−, logos, emoji.
- Corner cuts: `--cut-corner` / `--cut-corners-diagonal` tokens, redefined under [dir='rtl'].
- Numbers: only arithmetic is isolated left-to-right ('3 × 8–10', '3 × 45' then 'שנ׳', '2 / 3', '−2.7' then 'ק״ג'); "number unit"
  reads correctly without an isolate. Typed numbers / emails / passwords are LTR inputs aligned with the RTL labels (one global
  rule per app).
- Charts (weight / measurements / sparkline, dashboard trend): `<svg direction="ltr">` — time left → right, labels in the language.
- Week strip, day pickers, tab bar, tables: flex / grid follow the direction (Sunday on the right in Hebrew).
- Coach / user text (names, titles, notes, food names, meal names, options, tips, intro, summaries, Kaggle exercise names):
  `dir="auto"` or <bdi>, shown exactly as written.

5. DESIGN TOKENS — WHAT MOVED INTO packages/tokens/tokens.css
================================================================================
Colors and font sizes were already all tokens (no hex / px font-size outside tokens). Moved / added:
- Fonts: --font-heading-he / --font-body-he (system stack with Hebrew: system-ui, -apple-system, "Segoe UI", "Arial Hebrew",
  "Noto Sans Hebrew", Arial) and --font-heading-en / --font-body-en (Cabinet Grotesk / Satoshi, unchanged); --font-family-display /
  -body pick them by <html lang>. No font files added.
- Corner cuts: the clip-path polygon repeated in 12 CSS files (HomePage, AchievementBadge, AchievementTile, PlanCard, coach
  WorkoutLogList, TraineesPage ×2 (mobile + dashboard), BodySummary, PlaceholderPage, dashboard Login, …) → var(--cut-corner);
  the Countdown's two-corner shape → var(--cut-corners-diagonal); both mirrored for RTL.
- Border widths: ~213 declarations (1px / 2px / 3px / 4px) → --border-width-thin / -medium / -thick / -heavy.
- Focus ring: outline-offset ±2px (5 files) → --focus-ring-offset.
- Motion: --transition-fast/-base/-slow and --ease-standard/-out moved from apps/mobile/src/styles/animations.css; added
  --transition-progress (StreakRing 1s), --ease-emphasized (StreakRing curve), --loop-slow (2s scroll hint); StepVideoBackground's
  250ms ease-out → tokens.
- Opacity: 0.6 / 0.4 / 0.5 → --opacity-muted / --opacity-faint / --opacity-disabled.
- Layers: local z-index 0–3 (21 declarations) → --z-base / --z-raised / --z-overlay / --z-top (with --z-tab-bar, --z-modal).
- Shadows: none are used (flat design); --shadow-none added as the group's starting point.
- Breakpoints: --breakpoint-sm…-3xl (600 / 640 / 768 / 900 / 960 / 1024). CSS can't read a variable inside @media, so every
  media query keeps its number and now names its token in a comment — change both together (or add a build step later).
- Safe areas: --safe-inline-start / -end (follow the direction).

7. FONT NOTES FOR THE DESIGN PHASE (suggestions only — nothing applied)
================================================================================
The current Latin fonts have no Hebrew glyphs, so Hebrew uses the system-font placeholder. If the brand font is Barlow Condensed
(not in the code today — the tokens still say Cabinet Grotesk / Satoshi), possible Hebrew pairings (all free on Google Fonts):
- Heebo — a clean grotesque with 9 weights (100–900); the de-facto Israeli app font. Pairs well with Barlow for body text and as
  the Hebrew fallback for headings: font-family: "Barlow Condensed", "Heebo", sans-serif (the browser uses Barlow for Latin
  letters and Heebo for Hebrew, letter by letter).
- Karantina — a condensed, sporty Hebrew display face; the closest in feel to Barlow Condensed for headings, but only 3 weights
  (300 / 400 / 700) — headings only.
- Assistant — softer, 7 weights; an alternative to Heebo for body text.
A possible setup: headings --font-heading-he: "Karantina" (or Heebo Bold), body --font-body-he: "Heebo"; English
--font-heading-en: "Barlow Condensed". Only the four font tokens change.
